# Active Learning на IMDB

Учебное сравнение Random Sampling и Uncertainty Sampling при одинаковом бюджете
разметки. Небольшая Keras-модель обучается **с нуля на каждом этапе**. Проект
работает в терминале, сохраняет CSV и PNG, не требует GPU или веб-интерфейса.

Ориентир — [официальный пример Keras](https://keras.io/examples/nlp/active_learning_review_classification/).
Здесь упрощены модель и отбор: используется расстояние вероятности до 0.5.
Официальные train/test IMDB остаются раздельными; test не используется в цикле.

через `pip check`. Результаты находятся в [`results/quick/`](results/quick/).
Дополнительно проверены непересечение ID четырёх наборов, одинаковые бюджеты

| Стратегия | Test Accuracy | Test Precision | Test Recall | Test F1 | FP | FN |
|---|---:|---:|---:|---:|---:|---:|
| Random | 0.7050 | 0.7397 | 0.6092 | 0.6682 | 209 | 381 |

Это реальные метрики на 2000 тестовых отзывах после разметки 1000 обучающих.
В этом запуске Uncertainty повысил Recall/F1, но снизил Accuracy/Precision:

который был проигнорирован; обучение и сохранение результатов завершились успешно.

## Установка на macOS Apple Silicon

Используйте нативный ARM64 Python 3.11–3.13. В терминале из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Установленный TensorFlow запускается на CPU, включая Mac M1. Дополнительный
`tensorflow-metal` не нужен: программа явно отключает GPU. Первый запуск требует
интернета для загрузки архива IMDB (около 17 MB); затем архив используется из
`.cache/keras/datasets/imdb.npz`. Установка самого TensorFlow занимает существенно больше места.
При ошибке установки проверьте версию Python и `platform.machine()` (ожидается
`arm64`), доступ к PyPI и свободное место. При ошибке загрузки IMDB проверьте
интернет и сертификаты установленного Python; не отключайте проверку TLS.

Для повторения проверенного окружения после установки можно использовать
`python -m pip install -r requirements-lock.txt`. Это снимок конкретного окружения;
для другого Python или ОС сначала используйте основной `requirements.txt`.

## VS Code и команды

Откройте эту папку через File → Open Folder, установите расширение Python,
вызовите `Python: Select Interpreter` и выберите `.venv/bin/python`.
Откройте встроенный терминал и активируйте окружение, как выше.

```bash
python -m unittest discover -s tests -v
python main.py --mode quick
python main.py --mode full
python main.py --mode quick --epochs 5 --cycles 3 --query-size 300 --seed 7
python main.py --help
```

Без активации используйте `.venv/bin/python` вместо `python`.
Каждый запуск создаёт новую папку `results/<дата-время>/`; можно задать
`--output results/my-run`. Папка не должна уже существовать, чтобы случайно
не перезаписать прошлый эксперимент. Запускать команды можно и из другой папки:
пути к данным и стандартным результатам вычисляются относительно `main.py`.

| Параметр | Quick | Full |
|---|---:|---:|
| Начальная разметка | 500 | 1000 |
| Исходный пул | 2500 | 19000 |
| Validation | 1000 | 5000 |
| Test | 2000 | 25000 |
| Добавлений данных | 2 | 8 |
| Размер добавления | 250 | 1000 |
| Эпох на этап | 3 | 10 |
| Максимальная длина | 200 | 250 |
| Итоговая разметка для обучения | 1000 | 9000 |

Число обучений равно `2 × (cycles + 1)`. Quick проверяет весь путь, но обычно
слишком мал для убедительных выводов о качестве. Full может занять заметное
время на CPU; его следует выполнить до доклада. Время зависит от компьютера.
Все поля `Config` доступны через CLI, например `--initial-size`, `--pool-size`,
`--validation-size`, `--test-size`, `--batch-size`, `--learning-rate`.
Начальная выборка + пул + validation не должны превышать 25000, а
`cycles × query_size` — размер пула. Ноль циклов допускается.

## Как устроен эксперимент

1. Keras загружает IMDB: 25000 train и 25000 test, отзывы уже представлены
   целочисленными токенами. Используется готовый словарь датасета, он не
   переобучается на validation/test. Нули — padding, редкие слова — OOV.
2. Из официального train по seed выделяются непересекающиеся начальный набор,
   пул и validation. Для этого не используются классы, даже для балансировки.
   В Quick часть отзывов не используется. Test берётся только из официального test.
   Разбиение гарантирует отсутствие общих исходных ID между наборами;
   отдельная дедупликация похожих текстов исходного корпуса не проводится.
3. Обе стратегии начинают с одних и тех же размеченных отзывов. Модель:
   `Embedding(32, mask_zero=True) → GlobalAveragePooling1D → Dense(32, relu)
   → Dense(1, sigmoid)`. Padding исключён из среднего маской.
4. После обучения накапливаются метрики validation. Число эпох фиксировано;
   автоматического выбора лучшего этапа или настройки порога нет.
5. Random выбирает равновероятно без возвращения. Uncertainty предсказывает
   `p(положительный отзыв)` на оставшемся пуле и выбирает минимальные
   `abs(p - 0.5)`: например, 0.49 информативнее 0.95 по этому критерию.
   При равенстве расстояний используется воспроизводимый случайный порядок.
6. Только после выбора ID вызывается `LabelOracle.annotate()`. Истинные метки
   выбранных отзывов добавляются к обучению, отзывы удаляются из пула.
   Функция отбора не получает ни разметчика, ни истинных меток.
7. Создаются **новые веса и новый Adam**, обучение повторяется на всей
   накопленной выборке. Для одинакового номера этапа стратегии получают один
   seed и одинаковые настройки; seed этапа равен `seed + stage`.
8. После завершения обеих стратегий последние модели оцениваются на test
   один раз каждая. Тестовые метки не участвуют в отборе и настройке.

Разметчик — имитация интерфейса человека, а не механизм безопасности Python.
Загрузчик технически читает метки IMDB, но скрывает метки пула в двух независимых
разметчиках. Журналы запросов содержат классы **после** раскрытия. Один и тот же
отзыв может быть выбран разными стратегиями, но не дважды внутри одной стратегии.

Random Sampling — полезная базовая линия: он прост, не требует предсказаний на
пуле и проверяет, приносит ли интеллектуальный отбор пользу сверх самого
увеличения числа размеченных данных. Это последовательное обучение со случайной
разметкой, а не отдельная модель на всех доступных 25000 отзывах.

## Результаты и чтение графиков

В каждой папке запуска:

- `run.json` — настройки, версии библиотек, платформа и статус `complete` после
  успешного завершения. При аварийном завершении статус остаётся `running`;
  такие результаты неполны.
- `split_ids.npz` — исходные ID начального набора, пула, validation и test.
  ID test имеют смещение 25000 для отличия от train. ID относятся к порядку
  загрузки Keras с данным seed.
- `validation_metrics.csv` — обе кривые; `test_metrics.csv` — только итоговые
  метрики независимого test.
- `{random,uncertainty}_validation.csv` и `*_history.csv` — промежуточные
  метрики и loss/accuracy по эпохам; сохраняются после каждого этапа.
- `*_queries.csv` — выбранные ID, этап запроса, раскрытые метки и вероятность
  до разметки для Uncertainty. При нуле циклов этих файлов нет.
- `validation_accuracy.png`, `validation_f1.png` — качество на фиксированном
  validation в зависимости от числа размеченных **обучающих** отзывов.
- `final_test_comparison.png` — Accuracy, Precision, Recall и F1 последних
  моделей при одинаковом бюджете; это другой набор данных, чем на кривых.

На кривых выше — лучше. Сравнивайте точки с одинаковым X: преимущество активного
обучения означает лучшее качество при том же числе размеченных отзывов или
достижение сопоставимого качества при меньшем X. Первая точка должна совпадать.
Кривые могут пересекаться и снижаться. Из одного запуска нельзя заключать,
что одна стратегия всегда лучше.

Порог классификации фиксирован: `p >= 0.5` даёт класс 1. Accuracy — доля верных
ответов, Precision — доля положительных среди предсказанных положительных,
Recall — доля найденных положительных среди всех положительных, F1 — их
гармоническое среднее. FP — отрицательный отзыв, ошибочно названный положительным;
FN — положительный, названный отрицательным. FP/FN сохраняются как **количества**,
а не доли. При нулевом знаменателе Precision/Recall/F1 принимаются равными нулю.

## Ограничения и воспроизводимость

Установлены Python/NumPy/TensorFlow seed и детерминированные операции TensorFlow,
используется CPU. Побитное совпадение на разных версиях библиотек и оборудовании
не гарантируется. Сохранённые настройки и версии помогают повторить запуск.

Модель игнорирует порядок слов после усреднения, отзывы обрезаются, вероятности
не калибруются. Высокая неопределённость может означать шум или неоднозначность;
у небольшой плохо обученной модели она не обязательно означает полезность.
Разметчик идеален, цена каждого примера одинакова. Фиксированные эпохи дают
одинаковые условия между стратегиями на этапе, но больше обновлений весов на
более крупных выборках. Uncertainty дополнительно расходует время на весь пул.

Бюджет на оси X не включает заранее размеченные validation/test, общие для
стратегий: в реальном проекте за их разметку тоже нужно платить. Случайное
разбиение не гарантирует точного баланса классов. Официальный словарь IMDB —
готовый ресурс; здесь не воспроизводится его исходное построение.

Один seed не позволяет оценить статистическую значимость. Для более надёжного
сравнения повторите эксперимент с несколькими заранее выбранными seed и
сравните среднее/разброс при одинаковых бюджетах. Не выбирайте удачный seed
по test. Гиперпараметры можно исследовать на validation, но повторные решения
по test делают его частью настройки и нарушают независимость оценки.

## План демонстрации на 18 минут

1. 0–3 мин: задача дорогой разметки, общий бюджет и Random как базовая линия.
2. 3–6 мин: четыре набора, независимый test и интерфейс разметчика.
3. 6–10 мин: архитектура, формула `abs(p - 0.5)`, один цикл в `training.py`.
4. 10–14 мин: заранее сохранённые Full-графики и таблица FP/FN; Quick можно
   показать как проверку запуска, не ожидая Full во время выступления.
5. 14–18 мин: интерпретация, ограничения, вопросы. Если активный отбор проиграл,
   объясните это как результат конкретного эксперимента, не скрывайте его.
